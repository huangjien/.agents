# 2026-10-10 — `clear-technical-communication` v1.2 — relocated to canonical home

The user pointed out the new skill was at `~/.copilot/skills/`
(where it was originally placed per the design plan's literal
directory path) instead of `~/.agents/skills/` (where all 55
version-tracked skills live). I followed the plan without
re-checking the actual convention; that was the architectural
mistake.

   The 55 → 56 skills count in the lock file.

   `~/.copilot/copilot-instructions.md` to point to the new path.

## Folder hash algorithm (lock file)

The original installer algorithm is no longer present in the tree
(the 55 existing entries were generated by an external tool whose
source is gone). I used a stable, documented alternative: `sha1` of
the sorted concatenation of file contents. This is a deviation from
the installer's algorithm; the field is labeled with a `_note`
documenting the choice. If a re-install of this skill is later
triggered, the installer will compute its own hash and overwrite the
`_note` field — the rest of the entry format is the standard
local-skill schema.

**Validation done in v1.2 cleanup:** searched the agents tree
(`/Users/huangjien/.agents/`) for any script that reads
`.skill-lock.json` — none. `update-skills.py` reads SKILL.md
frontmatter and upstream metadata, not the lock file. The lock
file is read by an external installer whose source is not in the
current tree. The `_note` field is the only safety net; if a
re-install is ever triggered, the entry will be regenerated by the
installer's own algorithm and my note will be lost. Net: the
v1.2 lock-file entry is **pragmatic and currently safe**, but
**not guaranteed to survive a re-install**. A future v1.3 may
remove the `_note` field to keep the schema clean and let the
installer own its data.

## Why Copilot still finds it

`Personal: ~/.copilot/skills/ or ~/.agents/skills/`, so moving the
dir to `~/.agents/skills/` keeps it discoverable for both VS Code
Copilot and the CLI. Verified with `copilot skill list` (inherited
skills include clear-technical-communication).
